## Direction and routine choices

Proceed with one editable editorial-poster workflow, always creating a new document initially. Use Portrait 4:5, 1600 × 2000 pixels at 150 ppi as the initial default; expose size/resolution and warn about source resolution. These are routine, reversible implementation choices consistent with the owner's outcome-first direction, not reasons to block on another approval. Keep alternate formats available when tested. Call this a poster suitable for subsequent export checks; “print-ready” requires actual size/profile/font/format qualification.

The distinct art directions and actual command logs provide a useful vertical-slice starting point. Installed-font previews are explicitly machine-specific. Use bundled Inter and disclosed installed-font fallbacks initially; do not add font binaries or wait on upstream font licensing work. This review does not certify the visual quality of the JPEG previews or measured beginner success.

## Requirements before L3 apply can be accepted

1. **Failure restores session bookkeeping, not just pixels.** `Session::close(index)` selects a neighboring tab when closing the active document (`engine/src/lib.rs`); it does not necessarily return to the tab that was active before creating the poster. Snapshot the prior active document identity/index, document set and relevant journal boundary; on an injected failure remove only the owned new document, restore the prior active tab, truncate failed nested journal entries and preserve existing documents/history/dirty state. `jobs.rs::after_command` folds nested journal entries only after a successful outer command; it does not clean them on an error. Test with at least three open documents and the first active, plus no-document mode and failures after photo placement and after the final type step. Do not close an unrelated document by a stale index.
2. **Define undo of new-document creation accurately.** History is per document. The proposed `purge_last()` pattern can fold document edits, but does not make opening/closing a tab session-undoable. For the first version, one undo may return the new poster to its named blank starting document, with redo restoring the poster and source documents unchanged. State this in tests/UI rather than promising that Ctrl+Z returns the entire session to before Apply. If removing/recreating the tab is required, that is a separate session-history design.
3. **Prove folding under the smallest history budgets.** `History::record` trims while recording; deleting intermediate undo states afterwards cannot recover an already-evicted starting state. Test max states 1/2/default and a memory budget smaller than one representative image. Do not temporarily disable memory limits without bounding peak allocations. A staged document build with an explicit final history commit is an alternative, but must retain ordinary dispatch/authorization and bounded memory. Reusing the two-step frame pattern is not by itself proof for a 10–15-step recipe.
4. **Reconcile file acquisition and rollback.** The command map says file reads happen before rollback, but its apply outline places the file inside the multi-command scope. Choose and document one model: acquire/validate the user-authorized source before document mutation, then build from immutable prepared input; or explicitly scope and test the read inside Apply. Never bypass the caller's authorization in a temporary Session. Cancellation and late failure must not leave a new tab or a failed Actions entry. Hash/identify the source used for a preview so Apply cannot silently read different bytes.
5. **Use the pinned registry's journal contract.** In df055f3d, `actions_cmds::replayable` generally follows `CommandSpec::journal`; it does not need a new allowlist entry for every ordinary command. Do not automatically register a recipe containing a local path as replayable. Keep recording/replay disabled or explicitly unsupported until input rebinding, capability checks, missing/changed source and duplicate execution are tested. Re-read actual code rather than relying on a release binary's behavior or old planning assumptions.
6. **Bound determinism claims.** Same recipe inputs/version/seed should produce the same choices and equivalent editable content for a fixed input image, resolved fonts and color environment. Native document/layer IDs and metadata can vary. Compare normalized structure with references preserved, and pixels under stated font/color conditions; do not require byte-identical raw `.pcraft` files without handling volatile fields. Record the resolved fonts and recipe identity/seed in a persisted, inspectable form; renamed layer labels alone are not robust provenance.
7. **Qualify color and typography instead of silently converting.** Preserve the source document. RGB16/CMYK/Lab, embedded profiles, missing fonts and long/multiline titles require named checks before support is claimed. Title fitting must measure both width and height, retain a usable minimum size and handle unbreakable text. Pixel point samples do not establish whole-title contrast; treat the proposed contrast check as a bounded heuristic until its sampling method is tested.
8. **Complete repository attribution.** SOURCES.md records prototype sources and hashes. AGENTS.md also requires an `ATTRIBUTION.md` row for committed third-party/original assets; add those rows before the prototype assets are integrated. No source photographs or font binaries need to be added merely to close that documentation requirement.
